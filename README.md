# 豆瓣音乐 Top 250 数据爬取与可视化分析

Python 3.11 课程大作业。项目只有一个业务主程序：`douban_music_analysis.py`。

## 运行

使用项目现有的虚拟环境：

```bash
cd /Users/suis/Developer/2026-2027Works/Python_works/douban_music_analysis
.venv/bin/python douban_music_analysis.py
```

依赖为 requests、beautifulsoup4、pandas、matplotlib，已列在 `requirements.txt` 中。当前 macOS 环境使用 PingFang SC 显示中文图表。

每次运行都从零请求 `https://music.douban.com/top250` 的十个分页，页间隔 3 秒。不读取旧 CSV，不需要 repair 模式或人工合并。请遵守网站访问规则；程序不会绕过验证码或访问限制。

当前本机环境代理曾出现 TLS 握手中断，普通直连已验证可达。因此程序的 requests 会话默认直连（`USE_ENV_PROXY = False`），不修改系统代理配置，TLS 证书校验仍开启。如果所在网络确实需要使用环境代理，可将该常量改为 `True`。

- `运行核查.json`：以上数据的机器可读版本，包括 HTML 校验值和各图计数。

## 解析和统计规则

真实名次等于 HTML 的 `onclick` 中 `i + 1`，不使用 DOM 位置猜测名次，不重排缺口，也不补造唱片。

专辑名称和别名分列保存；`专辑ID`、链接和真实名次都要唯一。只有完全相同的重复记录会被删除；同名不同 ID 的唱片会保留，ID 或名次冲突会报错。

简介中的分隔符是两侧带空格的 `/`，因此 `2004/04/26`、`演唱会/Live`、`放克/灵歌/R&B` 不会被拆坏。多种类型标签一起保留；没有提供的字段留空或标为“未知”，同时保存 `原始简介` 和 `字段说明`。不因空字段删除唱片。

流派图和年代图覆盖全部 CSV 记录。评分图和散点图标明实际参与样本数及未参与数。歌手图按网页完整署名统计前十个及“其他歌手”，各组之和等于 CSV 条数，组合署名不会拆分后重复计数。

## 失败保护

HTTP 200 后仍检查榜单标题、当前页码、页尾、条目链接和真实排名。HTTP 403、418、429、验证页、截断页面或结构异常会停止运行。

临时连接中断、超时最多等待 5 秒后重试一次；不为凑足 250 条重试，不关闭 TLS 证书校验。失败时返回非零退出码，实际异常和失败证据保存在 `logs/`。

CSV、五张图和报告先在临时目录中生成并读回校验，全部成功后才整体替换 `output/`。上一份输出自动归档到 `history/output_时间/`；中途失败不会覆盖正式结果。历史源码保存在 `history/douban_music_analysis_full.py.bak`，无需运行。
